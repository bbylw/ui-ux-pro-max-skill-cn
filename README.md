```
                              │

│     • 匹配产品 → UI 分类规则                                      │
```

| **金融** | 金融科技/加密货币、银行、保险、个人财务追踪、发票与账单工具 |
| **医疗健康** | 医疗诊所、药房、牙科、兽医、心理健康、用药提醒 |
| **电子商务** | 综合电商、奢侈品、二手交易平台 (P2P)、订阅盒、外卖配送 |
| **服务** | 美容/水疗、餐饮、酒店、法律、家政服务、预约与预订 |
| **创意** | 作品集、代理公司、摄影、游戏、音乐流媒体、照片/视频编辑器 |
| **生活方式** | 习惯追踪、食谱与烹饪、冥想、天气、日记、情绪追踪 |
| **新兴技术** | Web3/NFT、空间计算、量子计算、自主无人机编队 |

每条规则包含：
- **推荐模式** - 落地页结构
- **风格优先级** - 最匹配的 UI 风格
- **配色氛围** - 适合该行业的调色板
- **字体氛围** - 与品牌个性匹配的字体
- **关键效果** - 动画与交互
- **反模式** - 不要做什么（例如银行业的“AI 紫/粉渐变”）

- **25 种图表类型** - 适用于仪表盘与数据分析场景的可视化建议
- **22 种技术栈** - React、Next.js、Astro、Vue、Nuxt.js、Nuxt UI、Svelte、SwiftUI、React Native、Flutter、HTML+Tailwind、shadcn/ui、Jetpack Compose、Angular、Laravel、Three.js、JavaFX、WPF、WinUI 3、UWP、Avalonia、Uno Platform

- **192 条推理规则** - 行业专属的设计系统生成（v2.0 新增）

### 弹性文本与紧凑型 UI

本节指南覆盖标题、长 token、chip、badge 以及微交互被中断等常见生产环境问题：

- 标题的平衡换行属于渐进增强（progressive enhancement），并不保证某个特定单词一定落在最后一行。设计仍需在各种宽度、字体和语言环境下依靠自然换行正常工作。
- 关键文本在窄视口、浏览器缩放、文字缩放和用户字距覆盖设置下必须能够重排而不被裁切。长 URL 与标识符应能安全换行。
- Chip 与标签集合应支持换行，或提供可操作的 `+n` 展开入口。紧凑标签在可行时应保持完整；无法避免的截断必须为键盘、指针和触屏用户提供可访问完整值的途径。
- 徽章（badge）的含义不能仅靠颜色传达。可交互 chip 需要原生语义、可见焦点和可编程状态；实时计数需要有意义的上下文。
- 快速连续操作可以取消动画，但最终的语义状态、焦点和内容必须保持正确。动画时长应依据平台与组件选择，并尊重“减少动态效果”偏好。

### 风格分类体系

目录包含 **79 种可检索风格**，均带有稳定 ID 和别名：

| 状态 | 数量 | 搜索行为 |
|------|-----:|----------|
| Active（活跃） | 50 | 参与常规推荐，并默认展示在画廊中 |
| Supplemental（补充） | 29 | 仅在精确名称或明确的变体/设计系统意图下返回；可通过画廊状态筛选查看 |
| Deprecated（弃用） | 9 | 不参与常规排名；旧名称会重定向到规范风格或落地页模式 |

活跃集合涵盖 43 个通用视觉家族、2 个移动端专用风格、3 个官方平台/设计系统、1 个平台材质和 1 个核心分析风格。当前的官方设计系统包括 Fluent 2、Shopify Polaris 和 Adobe Spectrum；Liquid Glass 被限定为 Apple 平台材质，Material 3 Expressive 保留为 Material 移动端变体，Spectrum 2 属于补充集。落地页结构存放在独立的 34 种模式落地页数据集中，不与视觉风格竞争 BM25 排名。

完整分类及来源元数据见 [`styles.csv`](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/src/ui-ux-pro-max/data/styles.csv)。

## 💎 基础版与高级版对比

许多用户询问开源版与高级版的区别。以下是详细对比，帮助你选择适合自己工作流的版本。

### 🟢 基础版（本仓库）
* **完全开源：** 适合个人开发者、爱好者和常规项目。
* **核心 UI/UX 智能：** 完整提供 79 种可检索 UI 风格（50 种活跃）、192 种产品类型、配色方案和精选字体配对。
* **智能推荐：** 内置 BM25 搜索引擎，实现高精度设计匹配。
* **跨平台支持：** 为 22 个主流框架（React、Vue、Tailwind、iOS、Android 等）提供栈专属指南。
* **设计系统生成：** 通过 CLI 即时生成定制化的 UI 规则、模式与逻辑。

### 🟡 高级版
* **扩展的品牌设计能力：** 超越 UI/UX 范畴，涵盖品牌识别生成、Logo 设计、企业识别系统 (CIP)、横幅、演示文稿幻灯片和自定义图标设计。
* **高级资产生成：** 深度集成 AI 图像生成能力，创建真实视觉资产而非占位符。
* **企业级架构：** 更完整、可扩展的设计 Token (Design Token) 架构，面向大规模团队部署。
* **优先支持：** 为需要不间断完整设计工作流的团队和专业人士提供专属技术支持。

👉 *如需了解升级到高级版的详情，请访问 [uupm.cc](https://uupm.cc)。*

## 安装

### 使用 Claude Marketplace（Claude Code）

在 Claude Code 中用两条命令直接安装：

```
/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill
/plugin install ui-ux-pro-max@ui-ux-pro-max-skill
```

```bash
# 全局安装 CLI
npm install -g ui-ux-pro-max-cli

# 进入你的项目
cd /path/to/your/project

# 为你的 AI 助手安装
uipro init --ai claude      # Claude Code
uipro init --ai cursor      # Cursor
uipro init --ai windsurf    # Windsurf
uipro init --ai antigravity # Antigravity

uipro init --ai kiro        # Kiro
uipro init --ai codex       # Codex CLI
uipro init --ai qoder       # Qoder
uipro init --ai roocode     # Roo Code
uipro init --ai gemini      # Gemini CLI
uipro init --ai trae        # Trae
uipro init --ai opencode    # OpenCode
uipro init --ai continue    # Continue
uipro init --ai codebuddy   # CodeBuddy
uipro init --ai droid       # Droid (Factory)
uipro init --ai kilocode    # KiloCode
uipro init --ai warp        # Warp
uipro init --ai augment     # Augment
uipro init --ai codewhale   # CodeWhale
uipro init --ai zcode       # ZCode
uipro init --ai kimi        # Kimi Code
uipro init --ai amazonq     # Amazon Q Developer
uipro init --ai openclaw    # OpenClaw (.agents/skills/)
uipro init --ai autoclaw    # AutoClaw (skills/ 或 ~/.openclaw-autoclaw/skills)
uipro init --ai universal   # Universal / Agent 标准 (.agents/skills/)
uipro init --ai all         # 所有助手
```

npm 包名为 `ui-ux-pro-max-cli`，安装后仍使用 `uipro` 命令。旧版 `uipro-cli` 已过时，不应继续用于获取当前资源。

### 全局安装（适用于所有项目）

```bash
uipro init --ai claude --global    # 安装到 ~/.claude/skills/
uipro init --ai cursor --global    # 安装到 ~/.cursor/skills/
uipro init --ai zcode --global     # 安装到 ~/.zcode/skills/
uipro init --ai kimi --global      # 安装到 ~/.kimi-code/skills/
uipro init --ai universal --global # 安装到 ~/.agents/skills/
```

### 其他 CLI 命令

```bash
uipro versions              # 列出可用版本
uipro update                # 从已安装的 CLI 包刷新 skill 文件
uipro update --global       # 从已安装的 CLI 包刷新全局 skill 文件
uipro init --offline        # 兼容性标志；安装随包捆绑的模板
uipro init --dry-run        # 预览安装动作，不写入文件
uipro uninstall             # 移除 skill（自动检测平台）
uipro uninstall --ai claude # 移除指定平台
uipro uninstall --global    # 移除全局安装
```

[安装 skill](#安装)后，在 AI 助手中打开你的应用，使用类似下面的提示词。工作流模式下请在提示词前加上 `/ui-ux-pro-max`。

```text
使用 ui-ux-pro-max skill 为我现有的 React 应用重新设计主题。
目标风格：极简主义与瑞士风格 (Minimalism & Swiss Style)。
```

**主题迁移检查清单：**

- **审计：** 在样式表、内联样式和工具类（如 `bg-blue-600`、`text-[#1e293b]`）中找出与主题相关的硬编码值。
- **映射：** 复用应用现有样式体系中的语义角色，如 `background`、`surface`、`foreground`、`primary`、`border`、`ring`；缺失角色按其所用库已安装版本的约定补充。
- **迁移：** 小批量地把硬编码值替换为 Token 引用。只修改 Token 本身，不会影响未使用这些 Token 的样式。
- **验证：** 每完成一批，检查文字/UI 对比度、悬停/焦点/禁用状态、响应式布局以及每个支持的主题。

### 工作原理

1. **你提出请求** - 提出任何 UI/UX 任务（构建、设计、创建、实现、审查、修复、改进）

3. **智能推荐** - 根据你的产品类型和需求，找出最匹配的风格、配色和排版
4. **代码生成** - 以正确的颜色、字体、间距和最佳实践实现 UI
5. **交付前检查** - 针对常见 UI/UX 反模式进行校验

### 持久化设计系统（Master + Overrides 模式）

把设计系统保存到文件，实现**跨会话的层级检索**：

```bash
# 生成并持久化到 design-system/myapp/MASTER.md
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp"

# 同时创建页面级覆盖文件
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp" --page "dashboard"
```

这会创建如下 `design-system/` 目录结构：

```
design-system/
└── myapp/                  # 每个项目一个目录（-p "MyApp" 的 slug）
    ├── MASTER.md           # 全局唯一事实源（颜色、排版、间距、组件）
    └── pages/
        └── dashboard.md    # 页面级覆盖（只记录与 Master 的偏差）
```

**层级检索的工作方式：**
1. 构建某个具体页面（如“结账页”）时，先检查 `design-system/[project-slug]/pages/checkout.md`
2. 如果页面文件存在，其规则**覆盖** Master 文件
3. 如果不存在，则只使用 `design-system/[project-slug]/MASTER.md`

**上下文感知检索提示词：**
```
我正在构建 [页面名称] 页面。请阅读 design-system/[project-slug]/MASTER.md。
同时检查 design-system/[project-slug]/pages/[page-name].md 是否存在。
如果页面文件存在，优先遵循其规则。
如果不存在，只使用 Master 规则。
现在，生成代码……
```

## 故障排查

### Claude Code 报错 `response exceeded the ... output token maximum`

这是 Claude Code 单次响应的输出上限，不是 UI/UX Pro Max 安装器或搜索脚本的错误。首先可以让 Claude 把任务拆成更小的步骤，并把较大的结果逐步写入文件。

如果你确实需要更大的单次响应，且当前使用的模型支持，可以在启动新会话前设置 Claude Code 的输出 Token 上限。例如：

```bash
# macOS、Linux 或 WSL
export CLAUDE_CODE_MAX_OUTPUT_TOKENS="64000"
claude
```

```powershell
# Windows PowerShell
$env:CLAUDE_CODE_MAX_OUTPUT_TOKENS = "64000"
claude
```

Shell 环境变量只对从该 Shell 启动的程序生效，因此设置后需要重启 Claude Code。Claude Code 会把超出当前模型输出上限的值收敛到上限；具体上限因模型和提供商而异。调大该值也可能增加延迟与用量，并减少自动压缩（auto-compaction）前可用的有效上下文。参见官方 [Claude Code 环境变量参考](https://code.claude.com/docs/en/env-vars#variables)。

### `uipro: unknown command 'uninstall'` 或 `unknown command 'update'`

你安装的 `ui-ux-pro-max-cli` 版本已过时。请更新后重试：

```bash
npm install -g ui-ux-pro-max-cli@latest
uipro uninstall
```

```bash
# 方案 A — 回到最初安装它的项目根目录运行
cd /path/to/your/project
uipro uninstall

# 方案 B — 移除全局安装
uipro uninstall --global

# 方案 C — 手动移除
rm -rf .claude/skills/ui-ux-pro-max   # Claude Code
rm -rf .cursor/skills/ui-ux-pro-max   # Cursor
rm -rf .windsurf/skills/ui-ux-pro-max # Windsurf
rm -rf .agents/skills/ui-ux-pro-max   # Antigravity / Codex
```

不要上传完整的 GitHub 仓库 ZIP。它是开发用代码检出，包含源代码、CLI 资源、文档、预览和多个捆绑 skill，会超出 Claude 的 200 个文件上传限制。它不是 Claude skill 上传包，本项目目前也不提供单独用于手动上传到 Claude.ai 的 ZIP。

```bash

```

或使用 CLI 安装器：

```bash
npx ui-ux-pro-max-cli init --ai claude
```

这是 v2.5.1 之前版本的已知问题。仓库内部使用过符号链接，某些安装工具无法处理。**解决办法：** 改用 CLI 安装器：
